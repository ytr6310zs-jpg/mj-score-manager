---
title: PLAN - Issue #265 一括インポートの取り込み上限撤廃
---

概要
--
Issue #265 は、一括インポートのパーサーに残っている 40 試合上限を撤廃し、41 以降の試合列と役満テーブル行も既存フローのまま取り込めるようにする改善である。変更範囲は主に `lib/spreadsheet-import.ts` とその回帰テストに限定し、UI や保存処理の契約は維持する。

現状把握
--
- `findMainHeaderRow` と `collectGameColumns` が 1..40 の上限に依存している
- `parseSpreadsheetMatrix` の主表ヘッダー警告と試合列警告が 1..40 を前提にしている
- `applyYakumanRows` でも `gameNo` の上限が 40 に固定されている
- `previewMatchImportAction` / `confirmMatchImportAction` 側は、パーサー結果をそのまま使っているため、パーサー修正が中心になる
- 自動テストは `test/spreadsheet-import.test.js` に parser レベルの回帰ケースを追加するのが最短である

設計方針
--
- 試合番号の上限判定をやめ、正の整数であることだけを判定する
- 主表ヘッダーは「player 系のラベル + 数値の試合列が少なくとも 1 つある」ことを引き続き要求する
- 役満テーブルは、対応する試合が存在する限り 40 超の `gameNo` を許可する
- 既存の 1..40 ケースは、警告文言も含めて非回帰で維持する
- ユーザー向け警告文言は、固定上限を連想させない表現へ更新する

実装ステップ
--
1. 現状調査と制御点の確定
   - 目的: 上限制御が残っている関数と警告文言を特定する
   - 完了条件: `lib/spreadsheet-import.ts` の 3 箇所の制御点が明文化されている
2. 主表ヘッダーの上限制御を撤廃する
   - 目的: 41 以降の試合列も `gameColumns` に入るようにする
   - 完了条件: `findMainHeaderRow` と `collectGameColumns` が 40 依存でなくなる
3. 役満テーブルの上限制御を撤廃する
   - 目的: `applyYakumanRows` で 40 超の `gameNo` を受け入れる
   - 完了条件: 41 以降の `gameNo` でも対応する試合へ紐づけられる
4. 警告文言を更新する
   - 目的: 1..40 固定の記述をなくす
   - 完了条件: ユーザー向けメッセージが動的上限前提の表現になる
5. 回帰テストを追加する
   - 目的: 既存ケースと 41+ ケースを固定する
   - 完了条件: `test/spreadsheet-import.test.js` に 40 超えの主表・役満テーブルケースが追加される
6. 動作検証を実施する
   - 目的: parser 変更がアプリ全体の一括インポートに悪影響を与えていないことを確認する
   - 完了条件: `npm test` と `npm run build` の結果を確認できる

検証計画
--
- 必須: `npm run build`
- 可能な限り実施: `npm test`、`npm run lint`
- 手動確認:
  - 41 試合目以降を含むシートを想定し、プレビュー上で試合が欠落しないことを確認する
  - 既存の 1..40 ケースで warning 文言やプレビュー件数が変わっていないことを確認する

リスクと対策
--
- リスク: 上限撤廃で、ヘッダーの誤検知が増える可能性がある
  - 対策: `player` 系のヘッダー判定と「少なくとも 1 つの数値試合列がある」条件は維持する
- リスク: 警告文言を更新し忘れると、40 上限が残っているように見える
  - 対策: テストで固定文言への依存を確認する
- リスク: テンプレート側とアプリ側の期待列数がずれると、運用に混乱が出る
  - 対策: Issue 本文の 80 局拡張前提を設計書に明記し、アプリ側は上限非依存にする

スコープ外
--
- UI レイアウト変更
- テンプレートファイルの再生成
- 既存の重複判定、権限制御、選択フローの再設計
