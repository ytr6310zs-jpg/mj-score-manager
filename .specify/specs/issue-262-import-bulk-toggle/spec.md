背景
--
スプレッドシート一括インポート画面では、プレビュー表示後に各行を個別に選択してから確定する運用になっている。現状はヘッダーに全体選択用のチェックボックスがなく、取り込み対象の ON / OFF をまとめて切り替えられないため、候補が多いと操作負荷が高い。

Issue #262 では、ヘッダーの「取込」列に一括チェックを追加し、個別チェックと全体チェックの状態を相互同期させることで、プレビュー後の選択操作を短縮する。

目的
--
- ヘッダーの「取込」に一括チェックを追加する
- 個別チェックの状態から一括チェックの ON / OFF / - を正しく同期する
- 一括チェックの操作で、候補行の選択状態をまとめて切り替えられるようにする
- プレビュー作成直後は、取り込み可能な候補がすべて選択済みになる既存挙動を維持する

ユーザーストーリー
--

### User Story 1 - 取り込み候補をまとめて選択できる (Priority: P1)
利用者はヘッダーの一括チェックを使い、表示中の取り込み候補をまとめて ON / OFF できる。

**Independent Test**: プレビュー結果が表示された状態でヘッダーの「取込」チェックを操作すると、対象行のチェック状態が一括で切り替わる。

**Acceptance Scenarios**:
1. **Given** プレビュー作成直後、**When** 一括チェックを見る、**Then** 対象候補がすべて選択済みである
2. **Given** 一括チェックが ON、**When** クリックする、**Then** 対象候補がすべて OFF になる
3. **Given** 一括チェックが OFF、**When** クリックする、**Then** 対象候補がすべて ON になる
4. **Given** 一括チェックが - 状態、**When** クリックする、**Then** 対象候補がすべて ON になる

### User Story 2 - 個別チェックと全体状態が同期する (Priority: P1)
利用者は個別行を操作したとき、ヘッダーの一括チェック状態から現在の選択状況を把握できる。

**Independent Test**: 一部の候補だけを OFF にすると一括チェックが - 状態になり、すべて OFF なら OFF、すべて ON なら ON になる。

**Acceptance Scenarios**:
1. **Given** 全候補が選択済み、**When** 1 行だけ OFF にする、**Then** 一括チェックは - 状態になる
2. **Given** 一部のみ選択済み、**When** すべての候補を ON にする、**Then** 一括チェックは ON になる
3. **Given** すべての候補が OFF、**When** 画面を確認する、**Then** 一括チェックは OFF になる

### User Story 3 - 既存の確定処理を壊さない (Priority: P1)
利用者は従来どおり選択済み行だけをインポートでき、確認処理や権限制御は変わらない。

**Independent Test**: 一括チェック追加後も、既存の選択済み行のみを送信する確定処理が維持される。

**Acceptance Scenarios**:
1. **Given** 何も選択していない状態、**When** 確定しようとする、**Then** 既存どおり 1 件以上選択が必要である
2. **Given** 選択済み行がある状態、**When** 確定する、**Then** 既存どおり選択済み行のみが送信される

受け入れ条件
--
- ヘッダーの「取込」列に一括チェックを追加する
- 個別行のチェック状態に応じて、一括チェックが ON / OFF / - を正しく表す
- 一括チェックのクリックで、表示中の候補行をまとめて ON / OFF できる
- プレビュー作成直後は、取り込み可能な候補が初期選択済みになる
- 既存の確定処理、権限制御、重複判定、競合解決の流れは維持する
- 自動テストは正常系のみを対象とする

制約
--
- 既存挙動を壊さない最小差分で実装する
- プレビュー結果が存在しないときは一括チェックを表示しない
- 取込不可行は従来どおり個別に disabled のまま扱う
- local Supabase 前提の安全運用を維持し、ローカル開発で staging / production の URL / key を混在させない
- 機密情報はコード / ドキュメント / ログに含めない
- CI / 運用の最低条件として `npm run build` を通す。可能なら `npm test` と `npm run lint` も通す

影響範囲
--
- `components/match-import-form.tsx`: 一括チェック UI と選択状態同期
- `test/e2e/ui/match-import.spec.ts`: 正常系の UI 確認を追加
- `docs/user-manual.md`: 必要なら操作説明を補足する

テスト
--
- Unit / UI: 一括チェックの初期状態、ON / OFF / - の遷移、個別操作による同期
- E2E: プレビュー作成後にヘッダーから全選択 / 全解除できること、個別操作で - 状態になること
- 回帰: 既存の確定処理と disabled 条件が変わらないこと

スコープ外
--
- インポート確定ロジックの再設計
- 競合解決フローの追加変更
- 取込不可行の仕様変更
