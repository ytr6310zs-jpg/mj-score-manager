---
title: PLAN - Issue #262 一括インポート画面 取り込み対象の一括チェック機能
---

概要
--
Issue #262 は、一括インポート画面のプレビュー表にヘッダー全体選択を追加し、個別チェックと全体チェックの状態を相互同期させる UI 改善である。既存の selectedRowIds 管理を活かし、フォーム送信や確定ロジックを変えずに最小差分で実現する。

現状把握
--
- プレビュー作成直後に、取り込み可能行は selectedRowIds に初期投入される
- 各行のチェック状態は selectedRowIds で管理されている
- 確定用フォームは selectedRowIdsCsv を hidden input で送信している
- 取込不可行は individual checkbox の disabled で扱われている

設計方針
--
- 一括チェックの状態は、表示中の選択可能行のみを基準に導出する
- 個別行が disabled の場合は全体選択の対象外とする
- 一括チェックは 3 状態を表現するが、クリック時の挙動は次の単純ルールに統一する
  - ON -> 全解除
  - OFF -> 全選択
  - - -> 全選択
- プレビュー結果が切り替わるたびに、一括チェック状態は現在の rows と selectedRowIds から再計算する
- 既存の確定ボタン、重複判定、競合解決ロジックには触れない

実装ステップ
--
1. 現状調査と UI 境界の再確認
   - 目的: selectedRowIds の所有者と、全体選択の計算式を確定する
   - 完了条件: 一括チェックの対象が「表示中の選択可能行」であると定義できている
2. ヘッダーに一括チェックを追加する
   - 目的: 取込列の見出しに三状態チェックを配置する
   - 完了条件: プレビュー表のヘッダーに一括チェックが表示される
3. 個別チェックとの同期ロジックを追加する
   - 目的: 全選択・部分選択・全解除を正しく導出する
   - 完了条件: 1 行の切り替えで - 状態を表現できる
4. 一括チェックの操作ロジックを追加する
   - 目的: ヘッダークリックで対象行をまとめて切り替える
   - 完了条件: クリック時に selectedRowIds が全選択 / 全解除へ遷移する
5. 正常系テストを追加する
   - 目的: 初期状態と代表遷移を固定する
   - 完了条件: E2E または UI テストで全選択 / 全解除 / 部分選択が担保される
6. 必要ならマニュアル文言を補足する
   - 目的: 運用説明と画面挙動を合わせる
   - 完了条件: ユーザーマニュアルに一括選択の説明が反映される

検証計画
--
- 必須: `npm run build`
- 可能な限り実施: `npm test`、`npm run lint`
- 手動確認:
  - プレビュー作成直後にヘッダーの一括チェックが ON になること
  - 一括チェックで全選択 / 全解除が切り替わること
  - 個別行を 1 件だけ外すと一括チェックが - になること
  - 取込不可行は disabled のままであること

リスクと対策
--
- リスク: 選択可能行と disabled 行を同一基準で扱うと状態がずれる
  - 対策: 一括チェックの導出対象を ready かつ disabled でない行に限定する
- リスク: 既存の初期選択処理と二重に上書きすると、プレビュー直後の状態が不安定になる
  - 対策: 既存の previewState 追従処理を基準に、派生 state を追加する
- リスク: 全体選択の ON / OFF が確定処理に影響する
  - 対策: hidden input に送る selectedRowIdsCsv の既存契約を維持する

スコープ外
--
- 取込不可行の選択可否変更
- server action の送信仕様変更
- 競合解決や重複判定の挙動変更
