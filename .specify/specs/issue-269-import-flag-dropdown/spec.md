背景
--
一括取り込みでは、プレーヤーごとのセルにスコアと状態フラグ（焼き鳥/飛ばし/飛び）を混在入力している。運用上の表記揺れや入力順の揺れにより、取り込み時の判定が不安定になりやすい。

Issue #269 では、各対局ごとに「スコアセル」と「状態セル」の2セル構成へ切り替え、状態セルは日本語ラベルの複数選択プルダウン（空/焼き鳥/飛ばし/飛び）で入力する前提に改める。これにより、一括取り込み時のフラグ解釈を明確化する。

目的
--
- 一括取り込みで扱う焼き鳥・飛ばし・飛びの入力ルールを選択肢方式に統一する
- 同時成立（焼き鳥/飛ばし/飛び の全組み合わせ）を正しく取り込めるようにする
- 内部保存値の扱いは既存データと同様に維持する
- テンプレート切り替えに伴う改修とし、後方互換や既存データ移行を不要とする

ユーザーストーリー
--

### User Story 1 - 新テンプレート入力を正しく取り込める (Priority: P0)
運用担当者は、対局ごとにスコアセルと状態セルを入力した新テンプレートを取り込み、期待どおりの状態で保存できる。

**Independent Test**: 新テンプレートの1試合分（状態セルあり）をプレビュー・確定し、保存結果が入力どおりであることを確認する。

**Acceptance Scenarios**:
1. **Given** 状態セルが 焼き鳥、**When** プレビューと確定を実行する、**Then** 焼き鳥だけが付与される
2. **Given** 状態セルが 飛ばし、**When** プレビューと確定を実行する、**Then** 飛ばしだけが付与される
3. **Given** 状態セルが 飛び、**When** プレビューと確定を実行する、**Then** 飛びだけが付与される
4. **Given** 状態セルが空（[]）、**When** プレビューと確定を実行する、**Then** 3フラグすべて未設定で保存される

### User Story 2 - 全組み合わせを取り込める (Priority: P0)
運用担当者は、状態セルの複合入力（焼き鳥+飛ばし、焼き鳥+飛び、飛ばし+飛び、焼き鳥+飛ばし+飛び）を指定でき、取り込み時に取りこぼしがない。

**Independent Test**: 複合状態の各パターンを含むテンプレートを取り込み、各フラグが期待通りに復元されることを確認する。

**Acceptance Scenarios**:
1. **Given** 状態セルが 焼き鳥+飛ばし、**When** 取り込む、**Then** 焼き鳥と飛ばしが付与される
2. **Given** 状態セルが 焼き鳥+飛び、**When** 取り込む、**Then** 焼き鳥と飛びが付与される
3. **Given** 状態セルが 飛ばし+飛び、**When** 取り込む、**Then** 飛ばしと飛びが付与される
4. **Given** 状態セルが 焼き鳥+飛ばし+飛び、**When** 取り込む、**Then** 3フラグすべてが付与される

### User Story 3 - 取り込み対象外の機能を壊さない (Priority: P0)
利用者は、手入力UIや既存データに影響を受けず、一括取り込みのみ仕様変更の恩恵を受ける。

**Independent Test**: 一括取り込み画面の変更後も、手入力画面および既存データ表示が従来通り動作することを確認する。

**Acceptance Scenarios**:
1. **Given** 一括取り込み改修後、**When** 手入力画面を利用する、**Then** 手入力UI仕様は変更されない
2. **Given** 既存データがある、**When** 一覧や集計を表示する、**Then** 既存の保存値解釈は変わらない

受け入れ条件
--
- 一括取り込みで、各対局の入力を「スコアセル」と「状態セル」の2セル前提で扱えること
- 状態セルは日本語ラベルの複数選択プルダウンで運用し、選択肢を次に固定すること
  - 空（未選択）
  - 焼き鳥
  - 飛ばし
  - 飛び
- 状態セルの許容値として、上記4選択肢に基づく全組み合わせを受理できること
- 空（[]）は未選択と同義で、フラグ未設定として扱うこと
- 同時成立（複合選択）をすべて正しく保存できること
- 状態選択肢の表示順が変更されても（例: 頻出順へ並べ替え）、取り込み判定が変わらないこと
- 内部保存値の扱いは既存データと同一ポリシーを維持すること
- 後方互換対応（旧テンプレート入力の解釈維持）は行わないこと
- データ移行は実施しないこと
- 改修対象は一括取り込み機能のみで、手入力UIはスコープ外とすること

制約
--
- Priority は P0（Issue 側で設定済み）
- テンプレートはアプリ改修と同時に切り替える前提とする
- 既存の保存スキーマ変更は行わない
- local Supabase 前提の安全運用を維持し、ローカル作業で remote URL / key を混在させない
- 検証の最低条件は build 成功。可能なら test と lint も実施する

影響範囲
--
- app/match-import-actions.ts: 取り込み時の状態セル解釈と payload 生成ルール
- lib/spreadsheet-import.ts: シート行列の解析ロジック（スコア列と状態列の対応づけ）
- components/match-import-form.tsx: 必要に応じた表示文言の調整（入力テンプレート案内）
- test/e2e/ui/match-import.spec.ts: 新テンプレート入力に対する正常系検証の更新

テスト
--
- パーサ単体観点
  - 単一状態（焼き鳥/飛ばし/飛び）
  - 複合状態（焼き鳥+飛ばし / 焼き鳥+飛び / 飛ばし+飛び / 焼き鳥+飛ばし+飛び）
  - 空状態（[] 相当）
  - 状態選択肢の表示順変更時でも同一入力値は同一結果になる
- 取り込みフロー観点
  - プレビューで状態が正しく反映される
  - 確定後に保存結果へ期待フラグが反映される
- 回帰観点
  - 手入力UIに影響がない
  - 既存データの解釈が変わらない

スコープ外
--
- 手入力UI（通常スコア入力画面）の入力方式変更
- 旧テンプレート互換の維持
- 既存データの再取り込み・移行
- DBスキーマ変更
