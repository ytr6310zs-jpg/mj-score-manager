---
title: PLAN - Issue #269 一括取り込み登録ルール改善（状態プルダウン化）
---

概要
--
Issue #269 は、一括取り込み向けスプレッドシートテンプレートを「スコアセル + 状態セル」の2セル構成へ移行する設計変更である。対象は一括取り込み機能のみとし、内部保存値の扱いは既存ロジックと同一に維持する。後方互換とデータ移行は行わない。

現状把握
--
- 現行のシート解析は、1セル内にスコアとフラグ文字列を混在入力する前提でトークン分割している
- フラグ解釈は Y / T / TB（および一部日本語別名）を許容する
- プレビューと確定は既存 payload 契約（payloadJson / selectedRowIds / conflictResolutionJson）で連携している
- 一括取り込み画面には既に行単位プレビューと確定導線がある

設計方針
--
- 解析対象を「スコア列」と「状態列」のペアとして扱う
- 状態列の値は空または定義済み組み合わせを受理する
- 状態列が空の場合は未選択扱い（フラグなし）とする
- 状態選択肢の表示順（頻出順への並べ替え等）には依存せず、セルに入った値のみを正規化して判定する
- Y / T / TB の複合成立を正規化して、既存保存形式（yakitoriPlayers / tobiPlayers / tobashiPlayers）へ落とし込む
- 一括取り込み以外（通常入力UI、集計UI）のロジックには手を入れない
- 旧テンプレート互換を維持しないため、曖昧入力救済ロジックは追加しない

実装ステップ
--
1. 解析仕様の確定
   - 目的: 列マッピング規則と状態値の許容パターンを固定する
   - 完了条件: 「試合番号ごとにスコア列・状態列を対で読む」ルールを明文化できる
2. パーサ更新
   - 目的: 状態列を専用解釈し、既存フラグ配列へ変換する
   - 完了条件: 全8パターン（空 + 7組み合わせ）を誤差なく解析できる
3. サーバーアクション整合
   - 目的: preview/confirm の payload と検証観点を新入力前提にそろえる
   - 完了条件: プレビュー表示と確定保存で同じ判定結果になる
4. UI案内文言の最小調整
   - 目的: 一括取り込み画面で新テンプレート前提を明示する
   - 完了条件: 利用者が入力ルールを誤解しない最小限の補足がある
5. テスト更新
   - 目的: 新テンプレート入力に対する正常系を固定化する
   - 完了条件: E2E または単体観点で全パターンの取り込みを確認できる

検証計画
--
- 必須: npm run build
- 可能な限り実施: npm test、npm run lint
- 重点確認:
  - 状態列が空のとき未選択として保存される
  - 単一選択（Y/T/TB）が正しく保存される
  - 複合選択（Y T / Y TB / T TB / Y T TB）が正しく保存される
   - 状態選択肢の表示順を入れ替えても判定結果が変わらない
  - 一括取り込み以外の画面や既存データ表示に回帰がない

リスクと対策
--
- リスク: 列ペア読み取りの実装で、試合番号列との対応がずれる
  - 対策: ヘッダー解釈時に「試合番号→スコア列/状態列」の対応表を明示的に生成する
- リスク: 空状態と不正状態の扱いが曖昧になり、意図しないフラグ付与が起きる
  - 対策: 空は未選択として許容し、不正値は警告または対象行要確認に寄せる
- リスク: 旧テンプレート互換を切ることで運用切替タイミングに混乱が出る
  - 対策: 画面文言と運用ドキュメントで新テンプレート必須を明示する
- リスク: プルダウン項目の並べ替え時に値比較ではなく位置依存で実装すると誤判定する
   - 対策: 表示順やインデックスを使わず、値文字列の正規化結果でのみ判定する

スコープ外
--
- 通常スコア入力UIの変更
- DBスキーマ変更
- 旧テンプレートの取り込み継続
- 過去データの移行作業
